# 资源雷达 · GitHub Pages 云端版

**特别感谢原作者 [ZiChuanLan](https://github.com/ZiChuanLan) 开源的 [Freebie Radar](https://github.com/ZiChuanLan/freebie-radar)。** 本项目是基于原项目采集能力的独立静态适配版，保留 MIT 许可及原始版权声明，不代表原作者官方服务。本项目复用固定提交 9191745d6368ca34b89f436abe2df66b9dd17d6e 的采集器，新增云端增量审核、静态网页与每日精选。欢迎支持原项目。

## 功能
- GitHub 托管 runner 每两小时采集，计划每日 12 次；北京时间 20:30 生成最多 12 条精选。首次通过 `bootstrap/initial-seed.json` 自动触发一次加大范围的补采，之后恢复普通配额。
- AI/开发者 4 条、电商 3 条、影音会员 3 条、其他 2 条；不足不凑数。
- 10 个公开数据源：LINUX DO、V2EX 两个节点、什么值得买、福利吧、IT之家、NodeSeek、OpenRouter、Epic、GamerPower。
- 淘宝、京东、拼多多、视频及音乐会员优惠通过公开聚合源发现，不是直接调用平台官方商品接口。
- 不推送，不开放本机端口，不使用 Lighthouse，不需要常驻服务器。
- 只读公开网页：分类、搜索、日期、近期资源和购物线索；无在线管理后台，不显示管理员配置入口或运行状态。

## 部署
1. Settings → Secrets and variables → Actions → New repository secret：名称 MIMO_API_KEY，值为自己的 MiMo API Key。不要提交密钥、数据库、Cookie、日志。可选 Actions Variable MIMO_MODEL，默认 mimo-v2.6-flash。
2. Settings → Pages → Build and deployment → Source: GitHub Actions。
3. Actions → Radar cloud collection and Pages → Run workflow（main）。可勾选 daily 提前刷新当日精选；可选 bootstrap 执行一次加大范围补采（会增加 AI 用量）。不勾选则正常采集。
4. 等待 collect / publish / deploy 全部成功，从部署日志或 Settings → Pages 获取真实网址。

## 运行边界
采集与审核分离，普通运行每源最多 20 条候选、每轮最多 24 条新候选送审；初始化补采每源最多 40 条、17 个源、最多 72 条送审，每批 2 条、串行，3 次批次错误即停止。已成功审核的指纹保留 14 天，不重复送审。无有效审核结果时保留上次快照。待审原始正文不持久化，仅在下次仍被源返回时重试。近 7 天资源、14 天日报历史；近期日报按链接和规范化标题去重。云端源可达性和模型实际响应需首次运行验证。模型 API 按实际用量收费。定时任务不保证精确准时，公开仓库长期无活动可能被停用。

## 安全
原始候选及 SQLite 仅存临时 runner；公开快照仅包含裁剪后的标题、来源、受限 HTTPS 链接、日期、质量及受控理由。网页以 textContent 渲染，不注入外部 HTML，禁用外部脚本。定时工作流不处理 Pull Request，采集 job 仅读，发布 job 才可提交公开 JSON，部署 job 才可使用 Pages 权限。MiMo Key 仅传给审核步骤。公开仓库及网页可被其他人访问，历史提交也可能留存公开记录。AI 评分不是官方核验，请核对原平台价格、资格、截止时间与续费条件。遵守来源条款和合理抓取频率。

## 初始化补采与信息量
- 初始化补采会在首次上传标记文件时自动运行一次（`push` 仅监视该文件）；后续每两小时仍使用原来的定时任务，不会反复触发高配额。
- 常规模式 15 个来源、每源最多 20 条、最多审核 24 条；初始化模式 17 个来源、每源最多 40 条、最多审核 72 条。只审查已清洗的公开资源候选，分类轮询避免单源霸榜。AI 审核可能产生一定 API 费用。
- 资源流可查看最近 7 天**通过审核**的记录；每日精选继续优先选择近 3 天、评分至少 4 星的最多 12 条。分类配额不足时可以由其他优质类别补位，仍然严格去重和不过期。不满足条件时少于 12 条属于正常结果。
- 资源站点是否可从 GitHub runner 访问、RSS 本身历史是否丰富以及 AI 是否通过审核，会影响实际收录量；不保证达到具体条数。原始抓取内容及 API Key 仍不会上传到公开仓库。

## 电商优惠实际覆盖与审查
- **不是**淘宝、京东、拼多多官方接口直采；购物资讯通过什么值得买、V2EX 优惠信息及其他公开聚合来源发现，出处会在卡片上如实标注。
- 当前对什么值得买的合法 RSS 商品条目优先归入购物候选，再要求模型核对是否有明确商品价格/折扣/优惠券；纯广告仍拒绝。普通审核保留至少 8 个购物审查位，只有通过审核的记录才公开。
- 仅更新一次的零售复查由 `bootstrap/retail-refresh.json` 新增事件触发，审查上限 36，随后回到每两小时固定的 24 条审核。内部审核统计仅通过 GitHub Actions 日志供维护者排查，不随网页公开数据发布。
- 如需淘宝/京东/拼多多**官方商品实时价格及库存**，需另行申请并接入获授权的开放平台 API，当前不能宣称已经实现。

## 历史版本：半小时更新、双路 MiMo 审核与免费社区数据源（已由下方新策略替代）

- 每 30 分钟运行轻量增量采集，每 2 小时执行原有来源的完整轮询；每日精选仍在北京时间 20:30 生成一次，不推送、不运行在用户电脑或 Lighthouse。
- 用户希望加速后，计划任务 **每轮最多审核 12 条新候选（原为 6 条）**，每批 2 条，最多 **2 路并发**。当 MiMo 返回非法 JSON 时仅重试该批次 1 次并提高回复 token 上限；其余失败不伪造通过记录。每两小时理论上限 48 条，约为之前的两倍，真实调用量与费用以跑批日志和官方账单为准。
- 优先维持券类、AI、新品和会员等分类平衡。对于 12 条的常规批次，先为最多 4 条券/红包留位，再给 AI、非券购物、会员等类别提供槽位，仍需经过原有 MiMo 判断才能进入正式资源。
- 用户不希望付费 X API，**移除 X 采集步骤、密钥注入及预算状态文件**；不会读写任何 X 帖文，也不使用绕过 X 登录的爬虫。
- 免费替代：Hacker News Algolia 的公共搜索接口（只采 3 天内含开发者免费试用/额度/折扣明确关键词的原创帖子，卡片链接到 HN 讨论原文）；Product Hunt 官方 `https://www.producthunt.com/feed` Atom 订阅源（每 2 小时轮询，仅保留近期明确提及优惠的公开新品）。两者不需要 API Key，严格校验 HTTPS 来源并为采集数与长度设定上限。
- 这些社区帖子都只是未经官方核实的候选，必须经过清洗、去重、MiMo 初筛；领券资格、活动时效仍以官方网页为准。网络不通/限流时仅跳过该源，其他来源保持工作。
- GitHub Actions cron 存在排队或偶发漏执行，不保证精确实时；若 MiMo 并发遇到限流或成本超预期，可以降低并发/每轮上限，不需要变更网站前端。

## 小红书公开索引线索（试行，2026-11-25）

- 小红书官方开放平台当前仅开放 `basic_info`，`read_notes`（读取笔记）仍处于规划阶段，无法用官方、免登录、完整实时的笔记 API。参考 https://openaccount.xiaohongshu.com/docs/scope 。
- 本项目不登录小红书、不读取私有笔记、不访问内部搜索接口，不保存 Cookie、作者信息、图片或任何所谓「XHS token」。**仅每两小时尝试从 Bing 公开 RSS 搜索索引发现** `xiaohongshu.com/explore/ID` 笔记，最多 2 个固定关键词搜索和 12 条索引线索，防止过多请求或误将其他站点链接当成小红书笔记。关键词集中在外卖红包、通用优惠券、会员福利和免费试用。
- 该来源的真实含义是「搜索引擎公开索引指向小红书的优惠笔记」，**不是小红书官方活动源**。搜索索引可能没有匹配结果、笔记过期、原文需要 App 或已删除。搜索索引的 pubDate 不等于原笔记发布时间，**不会声称是实时小红书最新笔记**。
- 只保留原始帖子链接、简短标题、固定的谨慎说明；强制使用 `https://www.xiaohongshu.com/explore/<hex-note-id>`，删除所有查询参数、广告跟踪字段和用户信息，禁止短链跳转。严禁分享/抓取个人笔记照片与正文。
- 所有候选再通过原有的 MiMo 检测、URL 白名单、标题安全清洗及去重流程，不自动进入每日精选。若无法抓取 RSS，仍正常完成其他来源的更新；本来源不会让 GitHub Action 失败。

### 小红书人工公开链接（公开索引的安全备用方式）

当搜索引擎找不到小红书笔记时，仓库维护者可以将**自己已确认公开的**优惠笔记标题、笔记规范链接以及加入日期，加入 `bootstrap/xhs-curated.json`，例如：

```json
[
  {
    "title": "此处填写真实优惠笔记标题（不是示例福利承诺）",
    "url": "https://www.xiaohongshu.com/explore/<真实笔记ID>",
    "addedOn": "2026-11-25"
  }
]
```

这是一个格式示例，**不要直接将这个占位符提交为真实资讯**。只有 7 天内加入且含具体优惠信号的合法公开笔记才会进入候选；仍然必须通过 MiMo 初筛才可公开展示。该列表当前为空；提交公开笔记标题/链接并不会自动登录小红书，也不会访问其正文或图片。**小红书部分裸链接可能无法在浏览器中直接打开**，用户需要在小红书 App 里按标题搜索原帖。投稿只需站长修改 GitHub 仓库文件，公众网页不公开后台编辑权限。

### 免费的公开笔记读者投稿（已接入）

- 因 Bing 公开索引在真实 GitHub Actions 首次验证时虽然返回 10 条搜索结果，但 **0 条是符合筛选条件的优惠笔记链接**，不能把试行索引称为已实现完整小红书抓取。
- 增加 [公开笔记优惠投稿](https://github.com/HardZionL/freebie-radar-pages/issues/new?template=xhs-offer.yml)：读者使用自己的免费 GitHub 账号提交一个公开笔记的标准 `/explore/...` 链接，Issue 标题以 `[小红书优惠]` 开头。
